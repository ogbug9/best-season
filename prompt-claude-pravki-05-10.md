## 2. Система состояний кнопок — ГЛАВНОЕ

### 2.1. Общие правила

1. **Один источник.** Цвета и стили default / hover / pressed / focus задаются один раз — CSS-переменные плюс классы-модификаторы по типам из 2.2. Мобилка использует те же классы и переменные. Мобильные переопределения цветов кнопок удалить. Исключение — у кнопки нет десктопного аналога: тогда оставить как есть и указать в отчёте.
2. **Никакой прозрачности при нажатии.** Касается всех кнопок:
   - в `:active` и нажатом состоянии запрещены `opacity < 1`, `rgba`/`hsla` с альфой < 1 у фона и рамки, `filter`, `backdrop-filter`, `mix-blend-mode`;
   - фон pressed — сплошной цвет из таблицы;
   - то же для `transition`: на время нажатия не должно мелькать прозрачное промежуточное состояние.
3. **Hover** — только внутри `@media (hover: hover) and (pointer: fine)`. Значения — из «Состояний кнопок» (радиальный градиент), если в таблице не сказано иное.
4. **Pressed** — `:active` и `.is-pressed`, если нажатие эмулируется в JS. На iOS Safari `:active` без слушателя `touchstart` не срабатывает: добавь один пассивный слушатель на `document` или проверь, что он уже есть.
5. **Focus** — `:focus-visible` по «Состояниям кнопок».
6. Состояние кнопки меняется только от взаимодействия с ней самой. Hover и нажатие на карточку не меняют кнопку внутри (правило 04.10 сохраняется).

## 6. Как проверять — обязательно, до push

Сделай скрипт `design/check_pravki_05_10.py` на Playwright. Он нужен и сейчас, и для будущих проверок — закоммить его. Скрипт работает с аргументом `--url` (локально и прод) и проверяет:

1. **Кнопки.** Для каждой кнопки из инвентаризации (этап 0, п. 2) на 1440 (мышь) и 390 (тач):
   - computed `background-color`, `background-image`, `color`, `border-color`, `border-width`, `opacity`, `filter` в default и pressed;
   - pressed совпадает с типом из 2.2 (допуск ±2 по каналу);
   - `opacity === 1`, `filter === none`, альфа фона и рамки = 1;
   - на 390 hover-стили не залипают после `tap`.

   Итог — таблица PASS/FAIL. **FAIL = не пушить.**
2. **Независимость кнопок от карточек.** Hover и нажатие на карточку (не на кнопку) не меняют computed-стили кнопки.
3. **Тексты.** Для блоков из разделов 4–5 со строками в макете:
   - через `Range.getClientRects()` получить фактические строки;
   - сравнить с макетом: число строк, первое и последнее слово каждой строки.

   Расхождение = FAIL.
4. **Отступы.** Для О2, мО2, мО3, мО6, мО7, мР1: `getBoundingClientRect` ключевых элементов против значений из SVG. Допуск ±2 px.
5. **Стрелка Д2** — по контролю из Д2.
6. **Регресс:**
   - горизонтальной прокрутки нет на 320, 390, 768, 1024, 1440, 1920 на всех страницах из этапа 0;
   - консоль без ошибок;
   - окно бронирования открывается.
7. **Снимки:** каждый блок «до / после / макет» рядом, в `tmp/pravki-05-10/final/` (не коммитить).

Значение в макете нельзя измерить — **не придумывай.** Отметь «не измерено» и спроси Данила.

# Инструменты сверки с макетом

Три файла, которые превращают «похоже на макет» в проверяемое утверждение.

## Зачем это нужно

До появления этих инструментов значения снимались со скриншотов на глаз.
Так в вёрстку попали заголовки 40px тёмно-зелёным вместо 90px оливкового,
кнопки 18px вместо 20px и ещё несколько ошибок, которые ловил заказчик,
а не разработчик. Это медленно и нечестно по отношению к нему.

Теперь порядок другой: значение измеряется один раз, записывается в
реестр, и дальше машина проверяет, что вёрстка ему соответствует.

## 1. `spec.json` — реестр измеренных значений

Единственный источник правды по типографике, цветам и размерам.

У каждого значения обязательно есть `source`:

| source | Что означает |
|---|---|
| `inspector` | Снято со скриншота панели Figma. **Факт высшей пробы.** |
| `reference` | Измерено программно с PNG-эталона макета. Тоже факт, но с точностью до пикселя растра |
| `derived` | Вычислено из фактов (например, затемнение цвета до нужного контраста) |
| `requirement` | Требование ТЗ, а не макета (например, 44px — минимальная цель нажатия) |
| `assumed` | **Догадка.** Подобрано на глаз, замер не делался. |

Соответствием макету считаются `inspector`, `reference` и `derived`.
Всё, что помечено `assumed`, — очередь на запрос скриншотов.

### Как измерять с эталона программно

Когда скриншота инспектора нет, но есть выгруженный PNG, значение можно
снять с него: границы блоков находятся по резкому изменению средней
яркости строки, цвет — по медиане пикселей в нужной полосе. Так были
получены высота первого экрана (877px), цвет заголовка и положение
кремовой панели (563px из 1440). Это точнее, чем на глаз, но грубее
инспектора: растр не знает про сетку и субпиксельные значения.

## 2. `check_spec.py` — проверка вёрстки против реестра

Поднимает headless-браузер, читает вычисленные стили и сравнивает.

```bash
# сначала должен быть запущен сервер
python manage.py runserver 8000 &

CHROME_PATH=/opt/pw-browsers/chromium python design/check_spec.py \
    --url http://127.0.0.1:8000/
```

Вывод делится на три части:

- **РАСХОЖДЕНИЯ** — вёрстка противоречит замеру. Это ошибка, код возврата 1.
- **ДОГАДКИ** — значение помечено `assumed`. Не ошибка, но и не соответствие.
- **НЕ НАЙДЕНЫ** — селектор не сработал. Обычно значит, что блок не
  выводится без контента.

Флаг `--strict` считает ошибкой и догадки. Включать перед сдачей этапа:
пока в реестре есть хоть одна догадка, говорить о полном соответствии
макету нельзя.

## 3. `compare.py` — попиксельное сравнение с эталоном

Считает на numpy: страница в 8000px обрабатывается за секунды, а не за
минуты — сверка гоняется после каждой правки, и скорость тут важна.

**Помнит прошлые запуски.** Складывает историю в
`design/out/<имя>-istoriya.json` и при каждом запуске показывает, стало
лучше или хуже, а главное — **какие полосы ухудшились после последней
правки**. Это ловит побочный ущерб: починил один блок, сломал соседний.

```bash
CHROME_PATH=/opt/pw-browsers/chromium python design/compare.py \
    --ref design/reference/glavnaya.png \
    --url http://127.0.0.1:8000/ \
    --whole
```

Рендерит страницу в ширине эталона и считает расхождение по
горизонтальным полосам. Выводит худшие полосы с координатами — так видно,
какая именно секция уехала.

Кладёт в `design/out/`:
- `<имя>-sravnenie.png` — три панели: макет, наш сайт, карта различий
- `<имя>-otchet.json` — числа по всем полосам, для отслеживания прогресса

Ключи:

| Ключ | Когда нужен |
|---|---|
| `--whole` | Эталон — весь фрейм целиком. Тогда проверяется и общая высота. |
| `--offset N` | Эталон — фрагмент, начинающийся не с верха страницы |
| `--band N` | Высота полосы замера, по умолчанию 100px |

**Важно про число расхождения.** Полного совпадения не будет, пока на
сайте нет тех же фотографий, что в макете: разные картинки дают разницу
сами по себе. Смотреть надо не на абсолютный процент, а на то, какие
полосы выделяются на фоне остальных, и на то, падает ли число от правки
к правке.

## Как получить эталон

В Figma выделить фрейм → `Ctrl+Shift+E` → PNG, масштаб **1x** →
положить в `design/reference/`.

Масштаб обязательно 1x: при 2x ширина удвоится и сравнение поедет.

## Как пополнять реестр

1. В Figma выделить узел
2. Скриншот правой панели: секции **Layout**, **Typography**, **Colors**
3. Значения переносятся в `spec.json` с `source: "inspector"` и указанием
   узла в поле `node`
4. `check_spec.py` покажет, где вёрстка расходится
5. Правится CSS, проверка гоняется снова до нуля расхождений

Лимиты Figma при этом не тратятся: скриншоты идут мимо коннектора.

# Инструкции проекта BS

## Режим экономии

- По умолчанию работаем только над кодом текущей задачи. Отвечать кратко, без повторов, больших планов и пересказа действий.
- Читать только нужные файлы и участки. Не обходить весь репозиторий и не перечитывать историю без необходимости.
- Самостоятельно выполнять необходимые правки кода и минимальные проверки корректности. Не запрашивать повторное подтверждение уже поставленной задачи.
- Только по прямому запросу: MCP/коннекторы, управление браузером и приложениями, скриншоты, генерация/экспорт/поиск изображений, Figma, визуализации, внешние сервисы и дополнительные инструменты.
- Присланные пользователем макеты и CSS использовать как исходные данные для кода. Сам факт передачи макета не означает запрос на скриншоты, MCP или экспорт.
- Только по прямому запросу создавать или изменять Markdown, HANDOFF.md, отчёты, реестр design/spec.json, память, инструкции и прочие служебные артефакты. Не обновлять их в конце каждой задачи или сессии.
- Фото по умолчанию заменять существующими заглушками; реальные изображения добавлять только по запросу.
- Не устанавливать зависимости, не скачивать ресурсы, не запускать серверы, фоновые задачи, агентов и автоматизации, не открывать вкладки и не устраивать уборку без запроса.
- Коммиты, push и выкладка — только по запросу.
- Проверять соразмерно изменению: синтаксис, точечные тесты, diff. Не запускать полный набор и браузерную сверку после каждой CSS-правки. Не создавать тесты, повторяющие простую реализацию.
- Если проверка невозможна, кратко указать ограничение. Не выдавать непроверенное визуальное совпадение за подтверждённое.
- Финал: что исправлено и существенный результат проверки, обычно 1–3 предложения. Не предлагать дополнительные работы без необходимости.

Эти правила заменяют прежний автоматический цикл «скриншоты → реестр → отчёт → HANDOFF». Старые задачи и отчёты не являются текущими поручениями.

## Технический контекст

Django 5 / Wagtail, Python, PostgreSQL; HTML-шаблоны, ручной CSS, Alpine.js, Swiper.js. Без React/Vue и сборки фронтенда. Бронирование — Контур.Отель, хостинг — Amvera.

- Шаблоны и статика: config/; разделы: home/, houses/, promotions/, reviews/, services/, forms/; общее наполнение: core/management/commands/seed_content.py.
- Сначала использовать .venv/Scripts/python.exe. Если Python311 отсутствует: доступный bundled Python + добавить .venv/Lib/site-packages в конец sys.path через append, чтобы не подменить совместимый PIL. Не чинить окружение и не устанавливать пакеты без запроса.
- Шрифты локальные, подключения: config/static/css/fonts.css. Montserrat 400/500/600, 300 italic; Etude Noire 400/500/700; Inter 400. Не подделывать отсутствующие начертания.
- Переносы макета закреплять в шаблонах/фильтрах. Не ломать типографику ради небольшой разницы метрик Chromium и Figma.
- У space-between фактический зазор считается по координатам, значение gap в панели может быть номинальным.
- Figma «Line height 100%» может обозначать Auto: использовать присланный явный line-height, иначе проверенный замер, не угадывать.
- Если отдельно запрошена работа с design/spec.json: только измеренные значения с источником; неизвестное — в открытые вопросы.

## По запросу на выкладку

origin — GitHub, историю хранит, сайт не обновляет. amvera — деплой; локальная ветка main, удалённая master: `git push amvera main:master`. Наполнение запускается контейнером автоматически. До выкладки — полный набор тестов и согласованные проверки. Не использовать `git add -A` вслепую: в рабочей папке могут быть временные файлы.
